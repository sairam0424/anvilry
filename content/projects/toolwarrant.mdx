**toolwarrant** is a Go control plane that defends MCP tool use against rug pulls, where an upstream changes a tool's definition after approval. It is for an operator who fronts MCP servers with agentgateway and wants a named person to approve the exact definition an agent can see. It is a single-author repository (not a fork) created on 2026-10-12, and claims no production deployment or third-party user.

- **Digest per definition** — SHA-256 over the RFC 8785 canonical JSON of the whole tool object, `_meta` included, with invalid UTF-8 refused.
- **Named approval** — `approve --hash` binds a person to one exact digest, and whoever crawled that digest cannot approve it.
- **Fail-closed serving** — as agentgateway's ExtMCP processor, it lists a tool only while its live digest equals the approved one, and denies a call whenever its evidence is missing or disagrees.
- **Drift handling** — a changed tool leaves the next `tools/list`, is flagged DRIFT, and can be re-approved, rejected or rolled back.
- **Signed audit log** — decisions and observed changes enter a hash-chained SQLite log in the same transaction, and since v0.4 human decisions are OpenSSH-signed.
- **Hardened crawler** — it refuses loopback, private, link-local and cloud-metadata addresses unless a server was added with `--allow-private`.
- **Gateway canary** — `verify-gateway` lists through the live gateway and compares the result with the catalog, the emitted file and the gateway's configuration.
- **Verifiable releases** — from v0.2.0 on, releases carry SPDX SBOMs, cosign-signed checksums and SLSA provenance; GitHub immutable releases are not enabled.

## Architecture

toolwarrant is one Go 1.27 module with 21 `internal/` packages and 5 `cmd/` binaries (only `toolwarrant` is released). The data plane is agentgateway v1.6.0 and toolwarrant never proxies MCP traffic: `serve` is an ExtMCP gRPC processor hooked on every `tools/list` and `tools/call`, one process per upstream, wired with `failureMode: failClosed`. The crawler talks to upstreams directly, never through the gateway. SECURITY.md describes the report of two inherited gateway behaviours to the agentgateway project as still pending.

State is one 0600 SQLite file (pure-Go modernc.org/sqlite, WAL) holding servers, tools, immutable versions, approvals, signed records and the audit log. Guard triggers refuse ordinary UPDATE and DELETE on history tables, and the operator trust list lives as signed records inside the audit chain.

CI runs `go test -race`, govulncheck, gitleaks and a docs job that fails when a cited test or link disappears. OpenSSF Scorecard read 7.7 on 2026-10-19, with 0 on Code-Review because pull requests are self-merged. Distribution is [GitHub Releases](https://github.com/sairam0424/toolwarrant/releases/tag/v0.4.0) and the [Go module proxy](https://pkg.go.dev/github.com/sairam0424/toolwarrant) only, and the README's opening still says v0.1.0 although v0.4.0 is the latest.

## How It Works

1. `init` creates the 0600 catalog and `trust init --ssh-key` records the signed trust list, printing a trust root and audit head that the operator keeps outside the database.
2. `server add` registers an upstream, and `crawl` lists its tools, hashes each canonicalised definition, and turns any unseen digest into an immutable version with a pending proposal.
3. `diff` and `show` grade drift CRITICAL, WARNING or INFO and refuse invisible characters and look-alikes unless `--accept-suspicious`; `approve SERVER TOOL --hash DIGEST` signs one exact digest over the audit head the approver read.
4. `emit` writes the agentgateway configuration with an explicit allow rule per route, and `serve --server NAME` starts the processor.
5. On every `tools/list` the processor keeps only tools whose live digest is approved; on every `tools/call` it denies unless the last listing and the last crawl both equal the approval, and anything it cannot decide is denied.
6. If an upstream edits a description, the tool vanishes from the next listing until a person re-approves, rejects or rolls back. `verify-gateway` and `audit verify` check the gateway and the chain; `verify-gateway --strict` is on `main` but unreleased.
