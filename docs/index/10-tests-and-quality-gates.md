## Runner topology (facts first)

- `pnpm build` = `velite --clean && vitest run && next build && pagefind …` (`package.json:11`; the script ends with `next build && pagefind --site .next/server/app --output-path public/pagefind`). **A failing Vitest assertion aborts the build before `next build` runs — so every test in this file is a deploy blocker on the Vercel build path.**
- `pnpm test` = `vitest run`; `pnpm test:watch` = `vitest` (`package.json:15-16`).
- `pnpm e2e` = `playwright test`; `pnpm e2e:ui` = `playwright test --ui` (`package.json:20-21`).
- **Two Vitest projects** (`vitest.config.ts:27-45`):
  - `node` — `environment: "node"`; include `["src/**/*.test.{ts,tsx}", "tests/**/*.test.{ts,tsx}"]`; exclude `["**/*.dom.test.{ts,tsx}", "**/node_modules/**"]` (`vitest.config.ts:30-35`). The exclude is load-bearing: `src/x.dom.test.ts` also matches `src/**/*.test.ts`, so without it every DOM suite would run twice — once without happy-dom globals.
  - `dom` — `environment: "happy-dom"`; include `["src/**/*.dom.test.{ts,tsx}", "tests/**/*.dom.test.{ts,tsx}"]` (`vitest.config.ts:38-43`). No explicit `exclude` — it relies on Vitest's default node_modules exclusion.
  - `tests/` does not exist in the repo; both include globs carry a `tests/**` arm that currently matches nothing.
  - `resolve: { tsconfigPaths: true }` (`vitest.config.ts:17`) is what lets tests import the real `@/*` modules and the generated `.velite` output rather than re-implementations.
- **`env: { NODE_ENV: "test" }`** (`vitest.config.ts:26`). Reason recorded in the config comment (`vitest.config.ts:19-25`): Vitest only defaults `NODE_ENV=test` when it is *unset*, but the Vercel build shell sets `NODE_ENV=production`; React would then load its production bundle, which strips `act`, and every `renderHook`/`render` DOM test would die with "React.act is not a function" and fail the deploy. Setting it in config is deterministic and scoped to the Vitest worker only — the separate `next build` process still runs in production mode.
- **`.velite/` is gitignored but required.** Many node-project tests import `@/lib/content` (which reads `.velite`), so CI generates it first: `pnpm content` runs before lint/typecheck/test in the `ci` job (`.github/workflows/ci.yml:54-55`, then the `Test` step at `.github/workflows/ci.yml:63-64`); the `e2e` job gets `.velite/` from `pnpm build`, whose first step is `velite --clean`.
- **Playwright** (`playwright.config.ts`): `testDir: "./e2e"`, `fullyParallel: true`, `forbidOnly: !!CI`, `retries: CI ? 2 : 0`, `workers: CI ? 1 : undefined`, `reporter: "html"`, `use.baseURL: "http://localhost:3000"`, `trace`/`video`: `"on-first-retry"`. **Two projects:** `chromium` (`devices["Desktop Chrome"]`) and `mobile-safari` (`devices["iPhone 13"]`) (`playwright.config.ts:15-24`); CI installs both engines (`playwright install --with-deps chromium webkit`). Specs branch on viewport width (below 640 px the nav drawer is opened; below 768 px the gamified-view and resume-PDF assertions change). 28 `test(` calls (20 in `views.spec.ts`, 8 in `resume.spec.ts`), 3 flag-ON tests skipped in CI on both projects and the one-line "Back to Classic" test (`views.spec.ts:131-145`, a phone constraint) skipped on `chromium`, so 24 + 25 = 49 executed runs and 7 skipped per pass. `webServer: { command: "pnpm start", url: "http://localhost:3000", reuseExistingServer: !process.env.CI, timeout: 120_000, stdout: "ignore", stderr: "pipe" }` (`playwright.config.ts:37-44`) — a production build must already exist, and the config comment (`playwright.config.ts:27-36`) records why the block exists: a stale server on :3000 silently made Playwright test an older build, producing 5 phantom "failures" during a release audit.
- **CI jobs** (`.github/workflows/ci.yml`; triggers: push to any branch, PRs to `develop`/`main`; five workflow files exist in total: `ci`, `codeql`, `dependency-review`, `gitleaks`, `scorecard`). Five jobs:
  - `ci` ("Lint · Type-check · Test", pnpm 10 at `ci.yml:24`, Node 22) = install → non-blocking `pnpm audit --audit-level high` (`continue-on-error`) → `pnpm content` (`ci.yml:54-55`) → `pnpm lint` → `npx tsc --noEmit` → `pnpm test` (`ci.yml:63-64`) → **Codebase index citations** (`node scripts/check-index-citations.mjs`, `ci.yml:76-77`) → **Claims integrity chain** (`npx tsx scripts/seal-claims.ts`, `ci.yml:83-84`, blocking).
  - `claims-integrity-autocommit` (opt-in, `needs: ci`, runs only when repo variable `SEAL_CLAIMS_AUTO_COMMIT == 'true'`) = `seal-claims.ts --write`, then commits `data/integrity-chain.json` with `[skip ci]`.
  - `e2e` ("E2E (Playwright)") = install → `playwright install --with-deps chromium webkit` → `pnpm build` (`ci.yml:176-177`; runs `vitest run` a second time) → **Bundle budget** (`node scripts/bundle-budget.mjs`, `ci.yml:190-191`, no `continue-on-error`) → `pnpm e2e` (`ci.yml:193-194`), uploading `playwright-report/` on failure. A comment on the job (`ci.yml:145-146`) records that the config's `webServer` block removed the need for a manual server step (the same comment cites the historical "5 of 19 tests" failing on dead selectors).
  - `install-pnpm-11` ("Install on pnpm 11", `ci.yml:204-253`) is the **only job that runs a pnpm other than the pinned 10**; its last step is `npx vitest run src/lib/pnpm-build-allowlist-consistency.test.ts` (`ci.yml:253`).
  - `security-alerts` ("Security alerts (report)", `ci.yml:255-331`) is `continue-on-error: true` (`ci.yml:279`) and always exits 0 by design.
- **`install-pnpm-11` exists because "CI passes" and "the repo installs" are different claims.** Every other job pins `version: 10` (`ci.yml:24`, `:108`, `:155`), so no green run had ever exercised the pnpm a contributor actually gets — `npm i -g pnpm` resolves to 11 (CI's `10` resolves to latest-10, which already honours `allowBuilds`, so the legacy lists are dead config there). That gap shipped a defect: pnpm 11 removed `onlyBuiltDependencies`/`ignoredBuiltDependencies` in favour of the boolean `allowBuilds` map, so `pnpm install --frozen-lockfile` exited 1 for every pnpm 11 user while CI stayed green, **and pnpm 11 rewrote the tracked `pnpm-workspace.yaml`** with a `set this to true or false` placeholder. The job installs cold (no store cache — a warm store can mask a resolution failure), then fails on `git diff --exit-code` so that silent write to a tracked file is itself a build failure, then runs the allowlist guard. It is a separate job rather than a step in `ci` because it must run a different pnpm major and must fail without masking lint/type/test.
- **The codebase-index citation check is NOT a Vitest suite.** It was briefly `src/lib/index-citations.test.ts`, which put it inside `vitest run` and therefore inside `pnpm build` — a stale doc would have failed the Vercel production build. That file is **deleted**; the check is now the CI-only step above, deliberately (the comment above that step records the reasoning — documentation freshness gates a merge, never a deploy, `ci.yml:71-72` — and the re-fingerprint command, `ci.yml:75`). It is therefore, together with the bundle budget and the claims-integrity chain, a quality gate in this file that is *not* a deploy blocker.
- **`scripts/check-index-citations.mjs` semantics.** Extracts `path:line` citations from `docs/index/*.md` (full path, partial path or bare filename forms; context-relative `(:44)` forms are counted, not verified) and compares each cited line's trimmed-text fingerprint against `docs/index/.citations.json`. Only a *stale* citation (recorded text found nowhere in the file, or duplicated at no position consistent with the file's observed line shift), a missing file/line, a blank target or an inverted range exits 1; a citation whose text merely *moved* is a warning. Flags: `--strict` (warnings also fail), `--write` (re-fingerprint; refuses while errors remain, and while warnings remain unless `--accept-warnings`), `--json`. Citations with no snapshot entry are informational only, unless they land on an empty line (still a blank-target error).
- **`scripts/bundle-budget.mjs` (CI `e2e` job, after `pnpm build`).** Reads `.next/diagnostics/route-bundle-stats.json` — emitted only by the default Turbopack build, so a `pnpm analyze` (`--webpack`) build makes it fail until `pnpm build` is re-run. Fails on: missing/malformed stats; fewer than `MIN_ROUTES = 17` route records (16 `page.tsx` routes plus `/_not-found`; the script says to fix the script, not lower the constant); any route whose first-load JS exceeds `MAX_FIRST_LOAD_BYTES = 1_336_000`; a first-load chunk that does not exist on disk; the string `WebGLRenderer` (three.js) in any route's first-load chunk set. Unmeasurable means red — this replaced `bundle-analysis.yml`, which produced zero artifacts in 222 runs and had no threshold, so it could never fail on bundle size.
- **`scripts/seal-claims.ts` + `data/integrity-chain.json` (CI `ci` job).** Verifies the hash chain is intact and that `profile.ts`'s current `impactMetrics`/`achievements` still hash to the last sealed entry. On drift, run `npx tsx scripts/seal-claims.ts --write` (or `pnpm seal-claims --write`) and commit the chain file. The chain primitives (`canonicalEncode`, `computeHash`, `buildEntry`, `verifyChain`, `currentClaimsMatchLastSeal`) are unit-tested in `src/lib/claims-integrity.test.ts` (inside `vitest run`); the CI step itself is not a deploy blocker.
- **No coverage provider or threshold is configured** (`vitest.config.ts`, `package.json`), so the workspace 80% rule is not enforced by any gate.
