# API Routes, Machine-Readable Endpoints & Instrumentation

> Part of the Anvilry v3.17.0 codebase index. Master entry point: [docs/index/README.md](./README.md)
>
> Describes Anvilry v3.17.0 (`package.json` 3.17.0), i.e. main `a929932` plus twenty-seven post-`a929932` changes in all, those that touch this scope described by behaviour, starting with five fixes: notes hidden at the data layer while `NOTES_ENABLED` is off; per-class rate-limit buckets (`chat` / `voice` / `beacon`) with a `CRON_SECRET` bypass for the eval cron and a shared `src/lib/cron-auth.ts`; one admin check (`isAdminAuthorized`) shared by `src/proxy.ts`, `requireAdmin` and the telemetry page; command-palette talk mode gated on `isVoiceViewActive`; `MIN_ROUTES = 17` in the bundle budget plus removal of dead components. v3.16.0 changes no route file here, only the data some of them read: the chat corpus (`src/lib/corpus.ts`, behind `/api/chat` and `/llms-full.txt`), the MCP project tools (`list_projects`, `get_project`) and `/api/resume.json` take a project's repo link from `repoLink()` in `src/lib/content.ts`, which is `null` for a private project (the corpus prints `Repo: private repository`, the two tools return `repo: null`, the resume entry's `url` falls back to the portfolio page); the `api/md/*` and `[slug].md` routes (through `markdownForContent` since the agent-readiness change below) still read the raw `content/` files, not the compiled bodies in `src/lib/content-bodies.ts`. v3.16.1 changes no route file here either: the removal of the `grpc-microservices` and `not-humans-lab` project cards leaves two fewer projects in the data the same routes read (the chat corpus, the MCP tools and `/api/resume.json`), and the new production gate's smoke script (`scripts/post-deploy-smoke.mjs`) requests only two real `/api` routes, `GET /api/resume.json` (it must be JSON with at least five projects) and `GET /api/cron/health-check` (an unauthenticated request must be refused with 401), plus, since the agent-readiness change, an `/api` path that does not exist (`/api/no-such-route` must answer a JSON 404 whose body has `code: "not_found"`), `GET /openapi.json` (OpenAPI 3.1.x with at least ten paths) and `GET /` with `Accept: text/markdown` (a Markdown body that starts with a heading, names the owner and sends `Vary: Accept`), while never requesting `/api/chat`, `/api/tts`, `/api/tts-google`, `/api/transcribe` or `/api/admin`. In v3.17.0, change (26), the agent-readable surface, is the one that does change this scope: it adds the shared JSON error shape `src/lib/api-error.ts` (`apiError`, `methodNotAllowed`, `ensureJsonError`) and applies it to the public and POST-only routes; a JSON 404 catch-all under `/api`; `GET /openapi.json`, built by `src/lib/openapi.ts`; and Markdown content negotiation, where `src/proxy.ts` grows from the `/admin` gate into a second job (`src/lib/accept-negotiation.ts`, `markdown-routing.ts`, `markdown-response.ts`, `markdown-content.ts`, `home-markdown.ts`), the eight `.md` handlers shrink to wrappers around `markdownForContent` and the two Markdown-only routes `/api/md/home` and `/api/md/not-found` appear. Change (27), the dependency security release, moves `@modelcontextprotocol/sdk` to 1.32.0 under the MCP route (`mcp-handler` 1.1.0 keeps its exact 1.26.0 peer) and changes no route file. Line citations are against that tree.

## Endpoint matrix

No file in this scope exports `runtime`. Route handlers therefore run on the **Node.js runtime** (Next's
default). `src/app/api/mcp/[transport]/route.ts:7-9` records that `export const runtime = "nodejs"` was
*removed* because `cacheComponents` rejects the export's presence, and that Node remains what runs.
`next.config.ts:205` sets `cacheComponents: true`, which is why every `revalidate` / `dynamic` segment
export in this scope was deleted (see the in-file comments cited below). `src/proxy.ts` also runs on the
Node.js runtime (Next 16's Proxy default, per its own docblock at `src/proxy.ts:9-10`), which is why it can
share `isAdminAuthorized` from `src/lib/admin-auth.ts` (`node:crypto`) instead of carrying its own Web
Crypto copy.

**JSON error contract.** Every failure a public route raises itself uses one JSON shape, `{ error, code, status, hint, docs }`, built by `apiError` in `src/lib/api-error.ts` (section below): `code` is the stable key to branch on, `hint` says what to do next and `docs` points at `/developers#errors`. A route that implements one method family also exports the other methods as `methodNotAllowed(...)`, so `GET` on a POST-only route (and the reverse) is a JSON `405` with an accurate `Allow` header instead of Next's empty-bodied one, and an `OPTIONS` handler (`optionsFor`) whose `Allow` matches it. This applies only to the **dynamic** routes (chat, tts, tts-google, transcribe, error, visit, `/api/github/stats`, the eight `.md` handlers and the MCP route): a route module that exports `POST`, `PUT`, `PATCH` or `DELETE` is treated by Next as dynamic, so the six prerendered GET routes (`/api/resume.json`, `/api/md/home`, `/llms.txt`, `/llms-full.txt`, `/feed.xml`, `/openapi.json`) export `GET` only and keep Next's default answer for other methods; `method-not-allowed.test.ts` pins both halves. The MCP route additionally runs every response through `ensureJsonError`, and a path under `/api` that no route matches is the JSON `404` of `src/app/api/[...path]/route.ts`. Out of the contract by design: the cron routes (`{ error: "Unauthorized" }`), the Vercel flags route (a `null` body), the FAQ-cache purge route's 401 and the proxy's 401 (plain text), and the JSON-RPC errors MCP clients parse. Markdown representations (`/index.md`, `<kind>/<slug>.md`, the proxy's rewrites) are a second contract: `Vary: Accept`, `Cache-Control: public, max-age=0, must-revalidate`, and a Markdown body even on 404.

The per-IP limiter is `checkRateLimit(req, cls)` from `src/lib/rate-limit.ts` with a **required** class
argument (`RateLimitClass = "chat" | "voice" | "beacon"`, `:19`). Each class is its own
`Ratelimit.slidingWindow(8, "60 s")` (`REQUESTS_PER_WINDOW`, `WINDOW`, `:22-23`; built in `buildLimiters`,
`:33-46`) under its own prefix (`anvilry:chat`, `anvilry:voice`, `anvilry:beacon`, `:25-29`), keyed by client
IP only. It **fails open** when Upstash env is unset (`:99`) or errors (`:106-108`), and a request carrying a
valid `Authorization: Bearer ${CRON_SECRET}` bypasses it (`hasValidCronSecret`, `:100`) so the eval cron's 12
sequential chats do not self-throttle. Class assignment: `chat` = `/api/chat`; `voice` = `/api/tts`,
`/api/tts-google`, `/api/transcribe`; `beacon` = `/api/error`.

### `src/app/api/chat/route.ts`

Attachment blocks are structurally validated — `image` requires `source.type === "base64"` and media type in `["image/jpeg","image/png","image/gif","image/webp"]` (:196-213); `document` requires `application/pdf` (:214-220); `text` blocks are capped at **10000** chars when they start with `"[PDF:"`, else `MAX_CHARS` (:232-240).

### FAQ response cache (`src/lib/chat-cache.ts`) and its purge route
- **Role:** Full-response cache for `/api/chat`, backed by the shared Upstash singleton (never a per-lambda `Map`), fail-open on every Redis error. Serves repeat first-turn questions with zero Bedrock spend.
- **Tiers:** exact (default on) — `normalizeQuestion` (trim, lowercase, collapse whitespace, strip trailing punctuation) → SHA-256 → key `anvilry:chat:cache:<hash>` (`faqCacheKey`, `:147-149`), and a stored `reasoning` is re-normalized on read because Redis is a trust boundary (`replayableReasoning` / `withReplayableReasoning`, `:173-186`, applied at `:281`); semantic (default **off**, `FAQ_CACHE_SEMANTIC_MATCH === "true"`, `:151-153`) — Titan embedding (`amazon.titan-embed-text-v2:0`, 512 dims, 5s timeout, `src/lib/faq-embeddings.ts:20-28`) compared against the capped index `anvilry:chat:cache:index`, hit when similarity ≥ `SIMILARITY_THRESHOLD = 0.92` (`:298`); the entry's `reasoning` field is deleted (`:326-329`) and the hit type is `Omit<FaqCacheEntry, "reasoning">` (`:124`), so a semantic hit never carries it. Whole cache kill switch: `FAQ_CACHE_ENABLED !== "false"` (`isFaqCacheEnabled`, `:159-161`).
- **Constants:** `FAQ_CACHE_TTL_SECONDS = 24 * 60 * 60` (`:68`, applied to the exact entry and, when the semantic tier is on, to its embedding re-write, `:394`, `:435`; the index sorted set has no TTL of its own); `FAQ_CACHE_INDEX_CAP = 500` (`:71`); index trims sampled 1-in-`TRIM_SAMPLE_EVERY = 20` writes (`:77`, `:402-408`); `MAX_CACHEABLE_ANSWER_CHARS = 4000` (`:84`); `MAX_CACHEABLE_REASONING_CHARS = 4000` (`:90`); `MAX_REASONING_QUESTION_CHARS = 200` (`:96`). Entries are tagged with the id of the deployment that wrote them (`ownDeploymentTag()`, `:193-195`, `VERCEL_DEPLOYMENT_ID`), so another deployment's answer is never replayed (a content-correcting deploy, a rollback, a preview reading production's entries) and a cold start changes nothing (one slot per question: a deployment that answers it again replaces the other's entry); only where the host gives no id is the tag `anvilry:corpus:built_at` (`src/instrumentation.ts`), re-stamped at every production process start.
- **Write gate:** `faqCacheSet` only stores when `finish_reason === "end_turn"` (`:361`), the sanitized answer is non-empty and ≤ 4000 chars (`:364`), and — upstream — `llm.ts` set `answerText` (clean, complete success only; every error path leaves it undefined; `reasoningText` rides along under the same condition, when non-empty) and the route saw `!attempt.fell_back` (`route.ts:470`): an answer served by a fallback rung is streamed but not cached, so a transient primary outage is not replayed for 24 h. It checks completion cleanliness, **not** content safety: a jailbreak that finishes cleanly is cached, which is what the purge route is for. The sixth parameter, `reasoning`, is stored beside the answer only when `replayableReasoning` accepts it (a string, control bytes stripped, trimmed, 1 to 4000 characters) and the normalized question is at most 200 characters, because the summary of a long question is the likeliest to carry what the visitor typed (`:371-374`); otherwise the answer is still cached without it, and an over-long summary logs only its length (`:375-383`).
- **Hit wire format:** one buffered body, not a stream: `answer + U+001E + JSON {model, fellBack:false, cacheHit:true, traceId}` with `X-Chat-Cache: hit` (:348-366). An exact-tier hit whose entry stored reasoning, with `EXTENDED_THINKING` not `false`, is prefixed `THINKING_SENTINEL` + reasoning + `THINKING_END` (:313-318, :356-358): the framing a live stream has, so `answerFromBody` and the chat client's parser read it unchanged, and the Chat view shows a collapsed "Thought for a moment" toggle. A semantic hit, an entry without reasoning and `EXTENDED_THINKING=false` get the plain body above. Clients must handle a non-streamed delimiter-format body in either shape; the frame never carries `usage`.
- **Purge — `POST /api/admin/faq-cache/purge`** (`src/app/api/admin/faq-cache/purge/route.ts`): `requireAdmin` (its own plain-text 401 with `WWW-Authenticate: Basic realm="anvilry"` and `Cache-Control: no-store`, not the shared JSON error shape; :33-34) → declared `content-length > 4KB` → **413** `payload_too_large` (:36-39) → `req.json()` failure → **400** `invalid_request` (:41-46) → post-read `JSON.stringify(body).length > 4KB` → **413** (:52-54) → `question` must be a non-empty string ≤ 2000 chars else **400** `invalid_request` (:59-65) → `faqCachePurge` (`chat-cache.ts:465-485`: `del` the entry key + `zrem` from the index; not gated on `isFaqCacheEnabled()`) → **503** when the result status is `error` (the bare result object, not the shared error shape), else **200** with `{status: "purged" | "not_found", key}` (:67-71). ### `src/app/api/cron/*` — the CRON_SECRET check
All five cron routes share **one** guard, `unauthorizedUnlessCron(req)` from `src/lib/cron-auth.ts:23-26`,
called first in the handler:

```ts
const denied = unauthorizedUnlessCron(req);
if (denied) return denied;
```

Locations: `eval/route.ts:102-103`, `health-check/route.ts:151-153`, `github-sync/route.ts:19-20`,
`seo-audit/route.ts:17-18`, `content-audit/route.ts:20-21`. The check itself is `hasValidCronSecret`
(`cron-auth.ts:15-20`): **fail-closed** — an unset/empty `CRON_SECRET` or a missing `authorization` header
returns false; otherwise both the supplied header and `` `Bearer ${secret}` `` are SHA-256 hashed and compared
with `crypto.timingSafeEqual` (constant-time, equal-length by construction, no scheme-case tolerance, no
trimming, no `x-vercel-*` alternative). The 401 body is `{ error: "Unauthorized" }`.
`src/app/api/cron/cron-auth.routes.test.ts` pins all five routes to this behaviour. The same
`hasValidCronSecret` is what lets the eval cron bypass the `chat` rate-limit bucket (`rate-limit.ts:100`).
Base-URL derivation, by contrast, is **not** uniform:
`eval/route.ts:105-107`, `github-sync/route.ts:32-34` and `seo-audit/route.ts:21-22` each inline
`process.env.VERCEL_URL ? \`https://${VERCEL_URL}\` : "http://localhost:3000"`; `content-audit` makes
zero network calls and needs no base at all; and `health-check` no longer reads `VERCEL_URL` directly —
it calls `probeBase()` from `@/lib/health-expectations` (`health-check/route.ts:155`,
`src/lib/health-expectations.ts:51-58`), which prefers `VERCEL_PROJECT_PRODUCTION_URL` and falls back
to `VERCEL_URL` only as a last resort. See the health-check section below for why that distinction is
load-bearing.

Schedules come from `vercel.json` (Vercel Cron issues **GET**):
`/api/cron/health-check` `0 5 * * *`; `/api/cron/eval` `0 9 * * 1`; `/api/cron/github-sync` `0 8 * * *`;
`/api/cron/seo-audit` `0 6 * * 1`; `/api/cron/content-audit` `0 7 * * 1`.

### `src/lib/accept-negotiation.ts`, `src/lib/markdown-routing.ts` and `src/next-config.test.ts`
- **`accept-negotiation.ts`:** the `Accept` rules, RFC 9110 section 12.5.1 as acceptmarkdown.com restates them. `PRODUCES = ["text/html", "text/markdown"]` (`:17`) is our order of preference, so HTML is the default. `negotiate(header, produces)` (`:62-90`) ranks each representation by the q of the most specific `Accept` range that matches it (`bestMatch`, `:49-56`: `text/markdown` beats `text/*`, which beats `*/*`); a matching range with `q=0` excludes it even when it is all we have; equal q is broken by the client's order, then by ours; a missing, blank, catch-all or unparseable header means no constraint and returns the first representation, HTML (`:66-69`); a header that only excludes types returns the first one not excluded (`:71-75`); `null` (a 406) comes back only when nothing we can produce is acceptable. `appendVary(headers, token)` (`:98-107`) adds a `Vary` token unless it or `*` is already there. The docblock says nothing outside this module may decide a representation, because `accept.includes("text/markdown")` is the classic wrong implementation. `mentionsMarkdown` (`:93-95`) is a substring pre-check that nothing but its own test calls (the proxy matcher does that job). `src/lib/accept-negotiation.test.ts` is 144 lines.
- **`markdown-routing.ts`:** `classifyPath(pathname)` (`:43-58`) decides what the proxy does with a path, as `MarkdownRoute`: `rewrite` (a Markdown twin exists), `pass` (leave the request alone) or `not-found` (a Markdown 404). `/` rewrites to `/api/md/home` (`:45`); `/admin` and the prefixes `/api/`, `/_next/`, `/_vercel/`, `/.well-known/` and `/admin/` pass (`:37`, `:47-49`), as does any last segment with a file extension (`FILE_EXTENSION`, `:40`: letters, digits and underscores up to 16 characters, because Pagefind ships `.pf_fragment`, `.pf_index` and `.pf_meta` files; so `.md` URLs, `robots.txt`, `sitemap.xml` and `llms.txt` pass) and the metadata images `opengraph-image`, `twitter-image`, `icon`, `apple-icon` (`:50-51`); `/<projects|work|articles|notes>/<slug>` (slug `[A-Za-z0-9_-]+`, `CONTENT_TWIN`, `:41`) rewrites to `/api/md/<kind>/<slug>` (`:53-54`); `HTML_ONLY_PAGES` (`:21-35`: `/about`, `/articles`, `/contact`, `/decisions`, `/developers`, `/mcp`, `/notes`, `/privacy`, `/projects`, `/resume`, `/search`, `/stats`, `/work`) pass (`:56`); everything else is `not-found`. ### `src/proxy.ts`
- **Role:** The Next 16 Proxy (formerly Middleware). It runs on the Node.js runtime (the Proxy default, docblock `:10-11`) before any route handler, and has two jobs (docblock `:11-23`): (1) return a real `401` with a `WWW-Authenticate` header for `/admin/*`, which an App Router server component cannot do (it must return React nodes) (`:13-18`); (2) Markdown content negotiation (https://acceptmarkdown.com, `:20-23`), so a request that asks for `text/markdown` gets the Markdown twin of a page.
- **Exports:** `config` (`:29-37`); `proxy(req: NextRequest)` (`:75-90`).
- **Matcher:** two entries: the string `"/admin/:path*"` and `{ source: "/:path*", has: [{ type: "header", key: "accept", value: "(.*)[Tt][Ee][Xx][Tt]/[Mm][Aa][Rr][Kk][Dd][Oo][Ww][Nn](.*)" }] }` (`:30-36`). The second wakes the function only for a request whose `Accept` header mentions `text/markdown` in any letter case, so browsers and crawlers that do not ask for Markdown never invoke it; the regular expression is spelled out letter by letter because a matcher value is a plain JS regular expression with no flags and media type names are case-insensitive (comment `:26-28`). The full rules (q-values, specificity, `q=0`) then decide per path. In practice the first entry covers `/admin/telemetry` (`src/app/admin/telemetry/page.tsx`); `/api/admin/*` (the FAQ-cache purge) does **not** match it and relies on `requireAdmin` alone.
- **Auth path** (`:78-87`): `proxy` first checks `pathname === "/admin"` or a path under `/admin/`, so the gate runs before any negotiation. It delegates the whole credential check to `isAdminAuthorized(req.headers.get("Authorization"))` (`:79`) from `src/lib/admin-auth.ts:24-44`, the single implementation shared by this proxy, `requireAdmin` (route handlers, `admin-auth.ts:48-50`) and the `/admin/telemetry` page (which re-checks and calls `notFound()` when unauthorized). It denies when `ADMIN_PASSWORD` is unset (logging an `[admin-auth]` warning on every denied call, never revealing why to the client), when the scheme is not `Basic `, or when the credential mismatches. The supplied value is decoded with `Buffer.from(_, "base64")` (never throws; garbage simply fails the compare) and both `"password"` and `"username:password"` forms are accepted, taking everything after the first colon (:37-41). The compare is `constantTimeEqual` — SHA-256 digests of both sides through `crypto.timingSafeEqual` (:55-59), so it is constant-time and length-safe. One 401 exit — `new NextResponse("Unauthorized", { status: 401, headers: { "WWW-Authenticate": 'Basic realm="anvilry"' } })` (`:80-83`) — serves every failure mode, so the response never distinguishes an unset env from a wrong password. Success returns `NextResponse.next()` (`:86`).
- **Negotiation path** (`negotiateMarkdown`, `:42-73`): `classifyPath(pathname)` (`src/lib/markdown-routing.ts`) first; `pass` returns `NextResponse.next()` (`:45`). Otherwise `negotiate(req.headers.get("accept"), PRODUCES)` (`:47`) picks the representation. `text/markdown` wins: a `rewrite` route is rewritten to its destination (`/api/md/home` for `/`, `/api/md/<kind>/<slug>` for a content page; `:49-50`), and a `not-found` route is rewritten to `/api/md/not-found?p=<pathname>` (`:51-53`), a real 404 with a Markdown body. Nothing acceptable (`null`) on a page that really is negotiated returns `406` with the plain-text body `NOT_ACCEPTABLE`, `Content-Type: text/plain; charset=utf-8`, `Vary: Accept` and `Cache-Control: no-store` (`:39-40`, `:58-67`); on any other route it falls through. Otherwise HTML wins: `NextResponse.next()`, with `Vary: Accept` appended for a negotiated route through `appendVary` (`:69-72`). `next.config.ts` (`headers()`, `:253-263`) adds the same `Vary: Accept` and a `Link: rel="alternate"` statically, so the proxy's `Vary` is the dynamic half of one contract.
- **Tests:** `src/proxy.test.ts` (162 lines) has three groups. The `/admin/*` gate: 401 with a challenge when `ADMIN_PASSWORD` is unset, with no `Authorization` header, with a wrong credential (including a same-length one) and with malformed base64; correct credentials pass in both forms. Markdown negotiation: the homepage twin, a content twin, an unknown path answered through the Markdown 404 handler with the path passed along, an HTML-only page, an API route and an explicit `.md` URL left alone, HTML with `Vary: Accept` when the client prefers HTML, HTML when Markdown is explicitly excluded even for a missing path, `406` for a negotiated page and no `406` for a page that is not negotiated, and the admin gate staying first for a client that asks for Markdown. The matcher: it still gates `/admin/*`, wakes only for an `Accept` header that mentions `text/markdown`, and (the newest case) matches that header in any letter case.
- **Gotchas / invariants:** the docblock (`:17-18`) calls the admin job the *first filter*, not the only gate: the admin pages re-check auth themselves. Because all three call sites (the proxy, `requireAdmin` and the page) use the same `isAdminAuthorized`, they can no longer disagree about a credential (previously the proxy carried its own Edge/Web Crypto copy with a plain `!==` digest compare). The `requireAdmin` 401 additionally sets `Cache-Control: no-store` (`unauthorized()` in `admin-auth.ts`); the proxy's 401 does not, and neither uses the shared JSON error shape. The second matcher entry matches every path, including `/_next/*` and static files, whenever the `Accept` header mentions Markdown; `classifyPath` is what makes those pass, by prefix and by file extension. A new extension-less page must be added to `HTML_ONLY_PAGES`, or a Markdown client is told it does not exist.

### `src/instrumentation.ts`
- **Role:** Next 16 server instrumentation hook — one structured config-snapshot log per server process start, plus a production-only process-start timestamp (the dashboard's Corpus age; the FAQ cache's tag only where the host gives no deployment id).
- **Exports:** `register()` (async).
- **Reads / depends on:** `process.env` only for the snapshot; dynamically `import("@/lib/redis")` at :96.
- **Behaviour notes:** returns immediately when `process.env.NEXT_RUNTIME === "edge"` (:35). Builds a `config` object with: `vercel_env` (enum of `production|preview|development`, fallback `"local"`), `node_env`, `region` (`VERCEL_REGION ?? AWS_REGION ?? "unknown"`), `deployment_id` (a boolean: `VERCEL_DEPLOYMENT_ID` is present, never the id), `flag_driver` (`vercel|local`, fallback `local`), `flags_sdk_configured` (`FLAGS` present), `flags_secret_configured` (`FLAGS_SECRET` present), a `beast_flags` block (`NEXT_PUBLIC_ORB_POSTPROCESSING`, `NEXT_PUBLIC_INK_TRANSITION`, `NEXT_PUBLIC_SKILL_TREE`, `NEXT_PUBLIC_404_ORB`, `NEXT_PUBLIC_VISITOR_COUNTER`, each `=== "true"`), an `integrations` presence-only block (`BEDROCK_ACCESS_KEY_ID`, `UPSTASH_REDIS_REST_URL`, `GOOGLE_TTS_API_KEY`, `GITHUB_TOKEN`, `ADMIN_PASSWORD`, `TELEMETRY_IP_SALT`), `llm_provider` (`bedrock|anthropic`, fallback `bedrock`) and `llm_sdk` (`anthropic-bedrock|aws-sdk-bedrock`) (:39-81). Emitted as a single `console.log("[config]", JSON.stringify(config))` (:85).
- **Gotchas / invariants:** only booleans and safe enum values are logged — never a secret value (:12-14). Grep handles are distinct and load-bearing: `[config]` here, `[trace]` for telemetry spans (`src/lib/telemetry/emit.ts:61`), `[vitals]` for RUM (`src/instrumentation-client.ts:52`), `[flags]` for flag resolution (`src/lib/flags.ts:45`). `discovery_badges` is deliberately omitted from `beast_flags` because it is runtime-resolved and logged by `getDiscoveryBadgesEnabled()` (:60-61). The corpus timestamp write (`anvilry:corpus:built_at`, `ex: 7 * 24 * 3600`) is gated on `VERCEL_ENV === "production"` — **not** `NODE_ENV`, because Vercel preview deploys also run with `NODE_ENV=production` and would pollute the value; it falls back to `NODE_ENV` only when `VERCEL_ENV` is absent (:87-105). The value is the current time in milliseconds (:98), written again by every production `register()`, i.e. at every process start (each cold start or fresh serverless instance), so it marks the last process start, not the last deploy. The FAQ cache does not use it where the host gives `VERCEL_DEPLOYMENT_ID`: an entry's `corpusBuiltAt` is then the writing deployment's id and a read is a hit only under the same id (`chat-cache.ts:193-195`, `chat-cache.ts:214-219`, `chat-cache.ts:280`), so cached answers survive process starts and end with their deployment; only without an id does a new stamp retire them. The docblock (:16-18) calls `register()` best-effort startup logging, but Next 16 awaits it (its docs: it "must complete before the server is ready to handle requests"), so a throw or a slow call there fails or delays every request on the instance; the Redis write is wrapped in try/catch for that reason.

### `src/instrumentation-client.ts`
- **Role:** Next 16 client instrumentation hook — registers web-vitals reporting and the two window-level error listeners that sit under the React boundaries.
- **Exports:** none. The whole file is a module-load side effect guarded by `if (typeof window !== "undefined")` (:46); the framework contract is "side-effects at module load are run" (:5-7).
- **Reads / depends on:** lazy `import("web-vitals")` (:50) and lazy `import("@/lib/telemetry/beacon")` (:59).
- **Behaviour notes:** `onLCP`/`onINP`/`onCLS` all report via `console.info("[vitals]", name, Math.round(value), rating)` — no Redis, no API route (:50-56); the whole vitals block is `.catch()`-swallowed so observability can never break the page. Two listeners are registered: `"error"` (:74) and `"unhandledrejection"` (:86), each calling `sendErrorBeacon` with `source: "window"` / `"unhandledrejection"`, `url: window.location.href`, `userAgent: navigator.userAgent`, `level: "error"`. Rejection reasons are narrowed four ways — `Error` instance, object with a string `.message` (and optional `.stack`), non-null primitive via `String()`, else the literal `"unhandled rejection"` (:93-106).
- **Gotchas / invariants:** the **dedupe contract** is the subtle part (:26-39, :65-72): React boundaries set `window.__anvilry_error_recently__ = Date.now()` *before* they beacon, and both window listeners suppress if that timestamp is within `DEDUPE_MS = 100`. It is a timestamp rather than a boolean specifically to avoid a `setTimeout` cleanup that would add an event-loop turn and re-create the race. Two genuinely distinct errors 200ms apart still both report. If a boundary stops setting that global, every render error double-reports to `/api/error`. Both `import()`s are dynamic to keep `web-vitals` (~4KB) and the beacon module out of the SSR bundle and off the critical path.
