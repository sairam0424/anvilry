# lib — Content, Data Derivation & Domain Model

> Part of the Anvilry v3.17.0 codebase index. Master entry point: [docs/index/README.md](./README.md)
>
> Describes Anvilry v3.17.0 (`package.json` 3.17.0), i.e. main @ a929932 (v3.6.0) plus five later fixes that touch this domain: notes are hidden at the data layer when `NOTES_ENABLED` is off, per-class rate-limit buckets (chat/voice/beacon) with a cron-secret bypass, admin auth shared through `isAdminAuthorized`, command-palette talk mode gated by `isVoiceViewActive`, and the bundle-budget `MIN_ROUTES` floor plus removal of dead components. Only the first changes code owned by this doc (`content.ts`, `llms-txt.ts`); the others are listed so a reader does not look for them here (rate limiting and auth live in the infra half of `src/lib`). v3.14.0 adds one module to this domain: `src/lib/stack.ts`, the home Stack wall's data — `STACK_ENTRIES` keyed by the exact `profile.skills` item strings, `stackItems` derived in profile order, `stackBrandVars()` — consumed by `src/components/home/stack.tsx` and `src/components/skill-chip.tsx`, with `src/lib/stack.test.ts` enforcing membership and 3:1 hover contrast; `profile.ts` itself is unchanged. v3.15.0 adds three more modules: `src/lib/mascots.ts` (the registry of the 14 drawn page-mascot characters as static WebP imports with screen-reader labels, `mascotSheets()`, the thirteen-strong `NOT_FOUND_MASCOTS` rotation and the pure `pickNotFoundMascot()`, which never repeats the previous pick), `src/lib/mascot-geometry.ts` (the sprite-sheet cell orders and the pointer-sector maths vendored from page-mascot 0.1.0, MIT) and `src/lib/mascot-flags.ts` (`isAboutMascotEnabled` / `isNotFoundMascotEnabled`, deliberately image-free so client code can read the flags); `profile.ts` and `stack.ts` are unchanged by it. v3.16.0 adds one more module, `src/lib/content-bodies.ts` (the compiled MDX bodies, split out of `content.ts` so that no client bundle carries them; the four body-only `*Bodies` Velite collections are read only there), and changes eight others to carry the twenty-entry project collection and the private-repository rule: `content.ts` gains `publicProjects` and `repoLink()` and a fourth entry in `projectGroups`; `graph-data.ts` grows from 16 nodes and 19 edges to 25 nodes and 28 edges; `game-model.ts` adds nine matching `NODE_CONTENT` entries, iterates `projectGroups` in `questGroups()` and reads `repoLink()` for the dossier; `github.ts` accepts `owner/name` allowlist entries (`isRepoAllowed()`, `repoOwnerAndName()`); and `profile.ts` (the hero repo metric), `corpus.ts`, `mcp-tools.ts` and `resume-json.ts` read `publicProjects` or `repoLink()`, so a private repository is listed but neither counted nor linked. v3.16.1 adds no module to this domain; it prunes the data these modules derive from: the `grpc-microservices` and `not-humans-lab` project cards are removed (18 projects remain, 16 of them public), `graph-data.ts` goes from 25 nodes and 28 edges to 23 nodes and 24 edges, `game-model.ts` drops the two matching `NODE_CONTENT` entries (`aava`→`aava-code` is now the only node id that differs from its content slug), `github.ts` drops three `REPO_ALLOWLIST` entries (`gRPC-micro-services`, `not-humans-lab` and `Shop.this`, 22 to 19), and `data/integrity-chain.json` gains a third sealed entry for the public-repository count of 16. v3.17.0 adds ten modules to this domain, all of them from its agent-readiness change (post-`a929932` change (26); branch `feat/agent-readiness`, five commits after the v3.16.1 tree, the third a review-fix commit) and all about how an outside agent reads the site: `site-url.ts` (the canonical origin), `accept-negotiation.ts`, `markdown-routing.ts` and `content-kinds.ts` (which representation a URL returns for a given `Accept` header, and the import-free list of content kinds the proxy needs), `markdown-response.ts`, `markdown-content.ts` and `home-markdown.ts` (the Markdown twins), `api-error.ts` (one JSON error shape), `openapi.ts` (the OpenAPI 3.1 description of the public API) and `privacy-facts.ts` (the numbers the privacy page prints); and it changes two: `profile.ts` gains `availability`, one sentence shared by `llms.txt` and the homepage Markdown twin, and `llms-txt.ts` gains the sections "When to use this site" and "How to read this site" and four links (developer guide, OpenAPI, contact, privacy). It also changes who imports `content.ts`: the eight `.md` route handlers no longer do, because they all go through `markdown-content.ts`. The other v3.17.0 change, (27), the dependency security release, adds no module and edits no file in this domain. The API-policy round after v3.17.0 (branch `feat/api-policy-ratelimit-md-twins`, HEAD `91381b5`, not yet released) adds seventeen modules to this domain, all about the public API contract and the Markdown twins of pages: `api-policy.ts` (the version, deprecation and rate-limit contract and its prose), `public-api-paths.ts` (which paths the proxy treats as public API), `api-catalog.ts` (the RFC 9727 API catalog), `content-api.ts` (what the `/api/v1` routes share), `json-schema-lite.ts` (a validator for the contract tests), five new `openapi-*.ts` modules (`openapi-parts.ts`, `openapi-schemas.ts`, `openapi-v1.ts`, `openapi-v1-schemas.ts`, `openapi-legacy.ts`) that split the OpenAPI document out of `openapi.ts`, which shrinks from 689 to 217 lines, `page-twins.ts`, `page-markdown.ts`, `page-markdown-lists.ts`, `page-markdown-prose.ts`, `page-markdown-shared.ts` and `element-markdown.ts` (the Markdown twins of pages), and `developers-content.ts` (the facts `/developers` states about the contract). It also changes four modules that already existed: `api-error.ts` (an eighth code, `internal_error`, and `withJsonErrors()`), `markdown-routing.ts` (`HTML_ONLY_PAGES` shrinks from thirteen pages to three), `llms-txt.ts` (a "Developer resources" block and a "Pages" list) and `privacy-facts.ts` (the public-API limit). The in-memory limiter for that contract, `public-api-limit.ts`, belongs to the infra half ([04](./04-lib-ai-voice-infra.md)). The agent-readiness round 3 after it (branch `feat/agent-readiness-round3`, HEAD `953db82`, not yet released) adds six modules to this domain: `batch.ts` (the logic behind `POST /api/v1/batch`), `home-articles.ts`, `article-href.ts` and `strip-tracking-params.ts` (pure modules shared by the homepage cards, the homepage JSON-LD lists and the homepage Markdown twin), `developer-tools.ts` (the `CLI.published` switch for the site's command-line wording, true in this change because the package is on npm) and `developer-states-support.ts` (test support for that switch). It changes `api-policy.ts` (`BATCH_MAX_RESPONSE_BYTES` and a rate-limit sentence about batches; `BATCH_PATH`, `BATCH_MAX_REQUESTS` and `BATCH_MAX_BODY_BYTES` were already in the tree at the base commit `d9bd6a8` of this round and are indexed here for the first time), `public-api-paths.ts` (a per-path method table and `allowedMethods()`; the module now imports `api-policy.ts`), `api-error.ts` (the `payload_too_large` wording), `content-api.ts` (`jsonResponse()` takes headers), the OpenAPI modules (the batch operation, the `x-read-only` marker and a generated opening sentence: 30 operations, `openapi.ts` is 261 lines), `mcp-tools.ts` (typed optional parameters, read-only annotations and the `TOOL_INPUT_SHAPES` registry), `home-markdown.ts`, `llms-txt.ts`, `page-markdown-prose.ts` and `developers-content.ts`.

**Scope:** `src/lib/*.ts` (top level only), content/data/domain half — `content.ts`, `content-bodies.ts`, `corpus.ts`, `decisions.ts`, `game-model.ts`, `graph-data.ts`, `article-grouping.ts`, `llms-txt.ts`, `profile.ts`, `stack.ts`, `mascots.ts`, `mascot-geometry.ts`, `mascot-flags.ts`, `personal.ts`, `testimonials.ts`, `resume-json.ts`, `mcp-tools.ts`, `claims-integrity.ts`, `integrity-chain.ts`, `discovery-store.ts`, `enabled-views.ts`, `flags.ts`, `writing-flags.ts`, `github.ts`, `utils.ts`, `highlight-store.ts`, the ten agent-readiness modules of v3.17.0 (`site-url.ts`, `accept-negotiation.ts`, `content-kinds.ts`, `markdown-routing.ts`, `markdown-response.ts`, `markdown-content.ts`, `home-markdown.ts`, `api-error.ts`, `openapi.ts`, `privacy-facts.ts`) and the seventeen modules of the API-policy round (`api-policy.ts`, `public-api-paths.ts`, `api-catalog.ts`, `content-api.ts`, `json-schema-lite.ts`, `openapi-parts.ts`, `openapi-schemas.ts`, `openapi-v1.ts`, `openapi-v1-schemas.ts`, `openapi-legacy.ts`, `page-twins.ts`, `page-markdown.ts`, `page-markdown-lists.ts`, `page-markdown-prose.ts`, `page-markdown-shared.ts`, `element-markdown.ts`, `developers-content.ts`) and the six modules of the agent-readiness round 3 (`batch.ts`, `home-articles.ts`, `article-href.ts`, `strip-tracking-params.ts`, `developer-tools.ts`, `developer-states-support.ts`); plus the CLI `scripts/seal-claims.ts` and the committed ledger `data/integrity-chain.json`. Excludes `*.test.ts` and the AI/voice/infra half (`llm*.ts`, `llm-trace.ts`, `agent-trace.ts`, `chat-cache.ts`, `faq-embeddings.ts`, `voice-*`, `rate-limit.ts`, `public-api-limit.ts`, `redis.ts`, `admin-auth.ts`, `cron-auth.ts`, `health-expectations.ts`, `metadata-colors.ts`, `theme-context.tsx`, `r3f.ts`, `use-*.ts`, `telemetry/`, `scroll/`).
**Files indexed:** 59 `src/lib` modules + 1 script + 1 data file (the 33 agent-readiness and public-API modules are rows 26-58 of the At-a-glance table, the 10 of v3.17.0 followed by the 17 of the API-policy round and the 6 of round 3, and are described under [Agent-readiness modules](#agent-readiness-modules))

There is **no `src/lib/avatar-glb.ts`** — `src/lib/avatar-glb.test.ts` is a standalone binary-asset invariant test that parses `public/avatar/sairam.glb` directly (`avatar-glb.test.ts:16`, budget `MAX_BYTES = 1.5 * 1024 * 1024` at `:21`). Likewise `notes.test.ts`, `notes-dark.test.ts` and `case-study-depth.test.ts` have no matching source module — all three test `content.ts`.

### Agent-readiness modules

- **`src/lib/accept-negotiation.ts`** (107 lines). Exports `PRODUCES` (`["text/html", "text/markdown"]`, in order of preference, `:17`), `negotiate()` (`:62`), `mentionsMarkdown()` (`:93`) and `appendVary()` (`:98`). The rules are RFC 9110 section 12.5.1: rank each producible type by the q of the most specific matching range (`text/markdown` over `text/*` over `*/*`), `q=0` means "never" even when it is all there is, equal q is broken by the client's order and then by `PRODUCES` order, and a missing, blank or catch-all header means no constraint (HTML wins). ### `src/lib/claims-integrity.ts`, `src/lib/integrity-chain.ts`, `scripts/seal-claims.ts`, `data/integrity-chain.json` — Claims Integrity Ledger
- **Role:** A hash chain over the résumé claim strings (`impactMetrics` + `achievements` from `profile.ts`) so a claim's stability since a specific commit is independently verifiable. It proves the strings have **not been silently edited since sealing**, not that they were ever accurate — there is no independent issuer, and every user-facing surface must say so (`claims-integrity.ts:1-16`). Simplified from Tombstone's Merkle-chain audit log: same length-prefixed encoding and prev-hash chaining, plain SHA-256, no locking (single writer).
- **`claims-integrity.ts` exports:** `ClaimsFields` (`:19-22`), `ChainEntry` (`{ seq, prevHash, hash, parentCommitSha, sealedAt, fields }`, `:24-31`), `canonicalEncode()` (`:39-46`), `computeHash()` (`:52-56`), `buildEntry()` (`:58-74`), `verifyChain()` (`:82-101`), `currentClaimsMatchLastSeal()` (`:104-113`). - **Mechanics:** `canonicalEncode` emits `<len>:<json>` for `impactMetrics` then `achievements` in fixed order — never delimiter-joined, so two distinct pairs cannot serialise identically. `computeHash` is `sha256:` + hex of `${encoded}${prev.length}:${prev}` with a null prev treated as `""`, so each entry commits to its whole history. `buildEntry` uses seq 1 / `prevHash: null` at genesis, else `prev.seq + 1`. `verifyChain` re-derives every hash and checks every `prevHash` link, returning the first broken `seq`. `currentClaimsMatchLastSeal` recomputes with the last entry's `prevHash` and compares to its `hash`.
- **`integrity-chain.ts`** (`:7-10`): imports `data/integrity-chain.json` directly (no `fs`), so it is safe in client components; consumed by the terminal `integrity` command (`src/components/game/terminal/commands.ts:242-288`, import at `:6`).
