## Route matrix

`cacheComponents: true` is set globally (`next.config.ts:235`, rationale comment from `:203`), so page routes are built as
`renderingMode: "PARTIALLY_STATIC"` with `experimentalPPR: true`. The "Render mode" column therefore records
what the *segment config + build artifact* say, not a pre-Next-16 static/ISR/dynamic trichotomy.
The `compute` / `response` / `initialRevalidateSeconds` values were read from a local, gitignored `.next` build made at 00:34 on 2 Nov, after HEAD
`953db82` (committed 19:15 on 1 Nov), from that source plus the CLI-published flip and the Testing Library waitFor limit, with `NEXT_PUBLIC_NOTES_ENABLED` unset (see UNVERIFIED); segment-config
facts (`"use cache"`, `cacheLife`, `instant`, `generateStaticParams`, `notFound()` gates) are re-read from source and are not env-dependent.

## Cross-cutting notes

- **Metadata-in-layout pattern.** Four routes put `metadata` in a sibling `layout.tsx` instead of `page.tsx`: `/resume`, `/search`, `/articles` (all three because the page is `"use client"` and Client Components cannot export metadata) and `/stats` (whose page *is* a Server Component — the layout is not required there). `/decisions` is a client page with **neither**, so it has no metadata at all.
- **`/stats` and `/search` are NOT route-gated.** `STATS_ENABLED` and `SEARCH_ENABLED` are consumed only by `src/app/sitemap.ts:90-108` and `src/components/site-nav.tsx:53-54`. Neither `stats/layout.tsx` nor `search/layout.tsx` calls `notFound()`, so both routes render and are prerendered even with the flags off — they are merely unlinked and un-sitemapped. Contrast `/articles` (gated in the layout, `articles/layout.tsx:12`) and `/notes` (gated in the page, `notes/page.tsx:21`, and at the data layer).
- **Hardcoded base URL.** `"https://anvilry.vercel.app"` appears literally in `layout.tsx:40`, `sitemap.ts:10`, `robots.ts:16`, `mcp/page.tsx:11`, and as `const BASE` in `articles/[slug]/page.tsx:14`, `notes/[slug]/page.tsx:14`, `projects/[slug]/page.tsx:25`, `work/[slug]/page.tsx:12` (plus `feed.xml/route.ts`, `json-ld.tsx`, `llms-txt.ts` and others outside this doc's scope). Newer machine-readable code imports one constant instead: `SITE_URL` in `src/lib/site-url.ts`, used by `api-error.ts`, `markdown-response.ts`, `home-markdown.ts`, `openapi.ts`, `json-ld.tsx`'s `OrganizationJsonLd`, `authorPerson()`, the new `json-ld-lists.tsx` and `json-ld-api.tsx`, and the `developers/sections/*` files, so a preview deployment never advertises itself as canonical. The authoritative check is `grep -rn 'anvilry\.vercel\.app' src Makefile`; at this revision it matches 85 lines in 46 files (`src/lib/site-url.ts` itself, tests and OG footers included; 26 lines in 22 files are outside tests and test support).
- **`cacheComponents` migration scars.** `work/page.tsx:9-13`, `notes/page.tsx:9-11`, `projects/page.tsx:32-37`, `projects/[slug]/page.tsx:67-70`, `notes/[slug]/page.tsx:17-25`, and `admin/telemetry/page.tsx:6-12` + `:471-477` each carry an in-file comment explaining a construct that was removed or added because `next.config.ts:235` sets `cacheComponents: true`. - **Raw-markdown URLs and `Accept` negotiation.** `next.config.ts:305-318` rewrites `/index.md` to `/api/md/home` (`:310`), `/:page(about|articles|contact|decisions|developers|mcp|notes|privacy|projects|work).md` to `/api/md/pages/:page` (`:313`) and `/{work,projects,articles,notes}/:slug.md` to `/api/md/<collection>/:slug`. The `src/app/<collection>/[slug].md/route.ts` files exist too (section 02); all of them, like the `/api/md/<collection>/[slug]` handlers, are thin wrappers around `markdownForContent` in `src/lib/markdown-content.ts`, so either path answers the same way, and the page twins are served by `markdownForPage` in `src/lib/page-markdown.ts`. `headers()` in `next.config.ts` (`:286-300`) also marks `/`, each of the ten `PAGE_TWINS` pages (`:292-295`) and `/<kind>/:slug` (slug pattern `[A-Za-z0-9_-]+`, so an explicit `x.md` URL does not match) with `Vary: Accept` and a `Link: <…md>; rel="alternate"; type="text/markdown"` header requested (Next replaces `Vary` on HTML responses, so on production only the `Link` arrives; the Markdown replies carry `Vary: Accept` themselves), and `/` additionally advertises `service-desc` (`/openapi.json`), `service-doc` (`/developers`) and `api-catalog` (`/.well-known/api-catalog`). When a request's `Accept` header asks for `text/markdown`, `src/proxy.ts` rewrites those same pages (and `/`, to `/api/md/home`) to the Markdown twin, answers a path that does not exist with a Markdown 404 and answers `406` when neither representation is acceptable. Of the 19 page files, the ten named above have a twin; `/resume` (a PDF viewer), `/search` (an interactive search) and `/stats` (live numbers) are HTML-only on purpose (`HTML_ONLY_PAGES`, `src/lib/markdown-routing.ts`, three entries since the API-policy round; it was thirteen) and pass through untouched.
- **Developer redirects.** `redirects()` in `next.config.ts` (`:302-304`) sends the addresses a developer, or an agent that guesses, tries for the API documentation, the SDK, the command line and the MCP server to the page that covers each, as permanent (308) redirects (`DEVELOPER_REDIRECTS`, `:108`): `/docs`, `/docs/api`, `/api-docs`, `/api-reference` and `/developer` to `/developers`, `/sdk` to `/developers#sdk`, `/cli` to `/developers#cli` and `/mcp-server` to `/mcp`.
