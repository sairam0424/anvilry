# API Routes, Machine-Readable Endpoints & Instrumentation

> Part of the Anvilry v3.17.0 codebase index. Master entry point: [docs/index/README.md](./README.md)
>
> Describes Anvilry v3.17.0 (`package.json` 3.17.0), i.e. main `a929932` plus twenty-seven post-`a929932` changes in all, those that touch this scope described by behaviour, starting with five fixes: notes hidden at the data layer while `NOTES_ENABLED` is off; per-class rate-limit buckets (`chat` / `voice` / `beacon`) with a `CRON_SECRET` bypass for the eval cron and a shared `src/lib/cron-auth.ts`; one admin check (`isAdminAuthorized`) shared by `src/proxy.ts`, `requireAdmin` and the telemetry page; command-palette talk mode gated on `isVoiceViewActive`; `MIN_ROUTES = 17` in the bundle budget plus removal of dead components. v3.16.0 changes no route file here, only the data some of them read: the chat corpus (`src/lib/corpus.ts`, behind `/api/chat` and `/llms-full.txt`), the MCP project tools (`list_projects`, `get_project`) and `/api/resume.json` take a project's repo link from `repoLink()` in `src/lib/content.ts`, which is `null` for a private project (the corpus prints `Repo: private repository`, the two tools return `repo: null`, the resume entry's `url` falls back to the portfolio page); the `api/md/*` and `[slug].md` routes (through `markdownForContent` since the agent-readiness change below) still read the raw `content/` files, not the compiled bodies in `src/lib/content-bodies.ts`. v3.16.1 changes no route file here either: the removal of the `grpc-microservices` and `not-humans-lab` project cards leaves two fewer projects in the data the same routes read (the chat corpus, the MCP tools and `/api/resume.json`), and the new production gate's smoke script (`scripts/post-deploy-smoke.mjs`, 30 checks in `CHECKS` at `:139`, 26 before the API-policy round) requests only a few real `/api` routes, `GET /api/resume.json` (it must be JSON with at least five projects) and `GET /api/cron/health-check` (an unauthenticated request must be refused with 401), plus, since the agent-readiness change, an `/api` path that does not exist (`/api/no-such-route` must answer a JSON 404 whose body has `code: "not_found"`), `GET /openapi.json` (OpenAPI 3.1.x with at least ten paths) and `GET /` with `Accept: text/markdown` (a Markdown body that starts with a heading, names the owner and sends `Vary: Accept`), and, since the API-policy round, `GET /api/v1` (version `"1"`, with the `API-Version` header and well-formed `RateLimit-Policy` and `RateLimit-Remaining` fields that `src/proxy.ts` stamps), `GET /api/v1/projects/does-not-exist-smoke-check` (a JSON 404 that still carries `API-Version: 1`), `GET /.well-known/api-catalog` (a linkset with a `service-desc` link) and `GET /about.md` (a Markdown twin that starts with a heading and names the owner), all `GET` only, while never requesting `/api/chat`, `/api/tts`, `/api/tts-google`, `/api/transcribe` or `/api/admin`. In v3.17.0, change (26), the agent-readable surface, is the one that does change this scope: it adds the shared JSON error shape `src/lib/api-error.ts` (`apiError`, `methodNotAllowed`, `ensureJsonError`) and applies it to the public and POST-only routes; a JSON 404 catch-all under `/api`; `GET /openapi.json`, built by `src/lib/openapi.ts`; and Markdown content negotiation, where `src/proxy.ts` grows from the `/admin` gate into a second job (`src/lib/accept-negotiation.ts`, `markdown-routing.ts`, `markdown-response.ts`, `markdown-content.ts`, `home-markdown.ts`), the eight `.md` handlers shrink to wrappers around `markdownForContent` and the two Markdown-only routes `/api/md/home` and `/api/md/not-found` appear. Change (27), the dependency security release, moves `@modelcontextprotocol/sdk` to 1.32.0 under the MCP route (`mcp-handler` 1.1.0 keeps its exact 1.26.0 peer) and changes no route file. The API-policy round after v3.17.0 (branch `feat/api-policy-ratelimit-md-twins`, not yet released) changes this scope more than any earlier one: a versioned JSON API under `/api/v1` (14 `GET` routes, 7 prerendered and 7 dynamic), the RFC 9727 API catalog at `/.well-known/api-catalog`, Markdown twins of ten pages (`/api/md/pages/[page]`, reached through `/<page>.md` and `Accept: text/markdown`), and a public-API contract that `src/proxy.ts` now enforces on every path `isPublicApiPath` accepts (an `API-Version` header, `RateLimit` headers, a per-client budget of 300 requests per 60 seconds held in server memory, a JSON 429, and for the read-only paths a JSON 405 and a 204 `OPTIONS`), with every number read from `src/lib/api-policy.ts`. The error catalogue grows from seven codes to eight (`internal_error`, with `withJsonErrors` behind it), `HTML_ONLY_PAGES` shrinks from thirteen pages to three, and the OpenAPI document grows from 15 to 29 operations across six modules. The 300-per-60-seconds budget and the 180-day deprecation notice are the maintainer's defaults, pending the owner's decision. The agent-readiness round after that (branch `feat/agent-readiness-round3`, code frozen at `953db82` apart from the CLI-published flip and the Testing Library waitFor limit, both made in the same change, also unreleased: `package.json` is still 3.17.0) changes this scope again: `POST /api/v1/batch`, the one public POST besides MCP, runs up to 25 distinct `/api/v1` GET operations in one request and counts as one request of the budget (`src/app/api/v1/batch/route.ts`, with its logic in `src/lib/batch.ts`, indexed in [03](./03-lib-content-data.md)); `public-api-paths.ts` gains a per-path method table (`allowedMethods`) that `src/proxy.ts` uses for both its JSON 405 and its 204 `OPTIONS`, and the proxy's version check moves into `versionRejection`; four MCP tools take typed optional parameters, all ten carry read-only annotations, and the MCP route answers `-32600` and `-32602` for requests the transport library handles wrongly and says `Allow: POST, OPTIONS` (v3.17.0 said `GET, POST, DELETE, OPTIONS`); the `payload_too_large` catalogue row covers an oversized answer as well as a body; the OpenAPI document has 30 operations (the batch operation `runBatch` is new), a POST that only reads carries `x-read-only` and the document's opening sentence is generated from those marks (`postRoutesSentence`); `jsonResponse` takes extra headers; the homepage Markdown twin takes its articles from the same selection and link rule as the cards; and the `llms.txt` Developer resources block has twelve lines (a batch line is new and the command-line line is worded by `CLI.published`, which this change sets to true because the owner published `anvilry` 0.1.0 to npm on 2026-11-01). Production runs the previous release (observed 2026-11-01): it has `/api/v1`, the page twins, the API catalog and the `RateLimit` headers, and none of the round-3 changes; its `llms.txt` and `/developers` still say there is no published CLI until this deploys. Line citations are against the tree at `953db82`; the CLI-published flip and the waitFor limit change no line count in a file this doc cites.

## Endpoint matrix

No file in this scope exports `runtime`. Route handlers therefore run on the **Node.js runtime** (Next's
default). `src/app/api/mcp/[transport]/route.ts:12-14` records that `export const runtime = "nodejs"` was
*removed* because `cacheComponents` rejects the export's presence, and that Node remains what runs.
`next.config.ts:235` sets `cacheComponents: true`, which is why every `revalidate` / `dynamic` segment
export in this scope was deleted (see the in-file comments cited below). `src/proxy.ts` also runs on the
Node.js runtime (Next 16's Proxy default, per its own docblock at `src/proxy.ts:13-14`), which is why it can
share `isAdminAuthorized` from `src/lib/admin-auth.ts` (`node:crypto`) instead of carrying its own Web
Crypto copy.

**JSON error contract.** Every failure a public route raises itself uses one JSON shape, `{ error, code, status, hint, docs }`, built by `apiError` in `src/lib/api-error.ts` (section below): `code` is the stable key to branch on, `hint` says what to do next and `docs` points at `/developers#errors`. A route that implements one method family also exports the other methods as `methodNotAllowed(...)`, so `GET` on a POST-only route (and the reverse) is a JSON `405` with an accurate `Allow` header instead of Next's empty-bodied one, and an `OPTIONS` handler (`optionsFor`) whose `Allow` matches it. This applies only to the **dynamic** routes (chat, tts, tts-google, transcribe, error, visit, `/api/github/stats`, the eight `.md` handlers, `/api/md/pages/[page]`, eight of the `/api/v1` routes, the batch route among them, and the MCP route): a route module that exports `POST`, `PUT`, `PATCH` or `DELETE` is treated by Next as dynamic, so the static GET routes (the six older ones, `/api/resume.json`, `/api/md/home`, `/llms.txt`, `/llms-full.txt`, `/feed.xml` and `/openapi.json`, plus the seven static `/api/v1` routes and `/.well-known/api-catalog`) export `GET` only; `method-not-allowed.test.ts` pins both halves for the older six, `v1-contract.test.ts` for the versioned GET routes and `batch/route.test.ts` for the batch route. What a static file cannot answer itself, the proxy now answers for it: a method that the path's entry in the method table (`allowedMethods`) does not list gets the same JSON `405` with that path's `Allow` (`GET, HEAD, OPTIONS` for a read-only path, `POST, OPTIONS` for `/api/v1/batch`), and `OPTIONS` gets a `204` with the same `Allow`, before the route is reached (see the `src/proxy.ts` section), so a prerendered file no longer falls back to Next's empty-bodied answer. An uncaught exception in a route wrapped in `withJsonErrors` (`/api/md/pages/[page]` and the dynamic `/api/v1` routes) leaves as the shared `500` `internal_error`, with the cause logged by name only. The MCP route additionally runs every response through `ensureJsonError` and answers the JSON-RPC errors the transport library gets wrong itself (see its section), and a path under `/api` that no route matches is the JSON `404` of `src/app/api/[...path]/route.ts`. Out of the contract by design: the cron routes (`{ error: "Unauthorized" }`), the Vercel flags route (a `null` body), the FAQ-cache purge route's 401 and the proxy's 401 (plain text), and the JSON-RPC errors MCP clients parse. Markdown representations (`/index.md`, `<kind>/<slug>.md`, the proxy's rewrites) are a second contract: `Vary: Accept`, `Cache-Control: public, max-age=0, must-revalidate`, and a Markdown body even on 404.

The per-IP limiter for the cost-bearing routes is `checkRateLimit(req, cls)` from `src/lib/rate-limit.ts` with a **required** class
argument (`RateLimitClass = "chat" | "voice" | "beacon"`, `:19`). Each class is its own
`Ratelimit.slidingWindow(8, "60 s")` (`REQUESTS_PER_WINDOW`, `WINDOW`, `:22-23`; built in `buildLimiters`,
`:33-46`) under its own prefix (`anvilry:chat`, `anvilry:voice`, `anvilry:beacon`, `:25-29`), keyed by client
IP only. It **fails open** when Upstash env is unset (`:99`) or errors (`:106-108`), and a request carrying a
valid `Authorization: Bearer ${CRON_SECRET}` bypasses it (`hasValidCronSecret`, `:100`) so the eval cron's 12
sequential chats do not self-throttle. Class assignment: `chat` = `/api/chat`; `voice` = `/api/tts`,
`/api/tts-google`, `/api/transcribe`; `beacon` = `/api/error`.

**The public-API budget is a second, separate limiter.** `src/proxy.ts` counts every request to a public-API path (`isPublicApiPath`: the `/api/v1` routes, `/api/resume.json`, `/api/github/stats`, the MCP endpoint, the `.md` twins and the discovery files `/llms.txt`, `/llms-full.txt`, `/openapi.json`, `/feed.xml`, `/sitemap.xml`, `/robots.txt` and `/.well-known/api-catalog`) against `publicApiLimiter` (`src/lib/public-api-limit.ts:99`), a fixed window per client IP: `RATE_LIMIT_POLICY` is 300 requests per 60 seconds (`src/lib/api-policy.ts:41-45`), and at most 10,000 clients are tracked (`DEFAULT_MAX_KEYS`, `public-api-limit.ts:36`; expired windows go first, then the oldest); the periodic sweep that removes a client that never returns runs at most once per window, at a request and never on a timer (`sweepExpired`, `public-api-limit.ts:50-55`, called from `hit()` at `:69-71`); a full table also sweeps when a new client arrives (`prune()`, `:57-64`, called at `:75`); and every counter is gone when the instance restarts. It lives in the memory of the server instance, **not** in Redis, on purpose: the routes it guards are free, read-only and mostly cached, and a crawler must not be able to burn the Upstash quota the chat cost guard depends on. The cost is stated in the published policy: the count is per server instance. The budget never applies to `/api/chat`, the voice routes, `/api/error`, `/api/visit`, the admin and cron routes, `/` or any HTML page, and it does not count an `OPTIONS` preflight, a request refused for an unsupported `API-Version`, or a method the path does not take, refused with a 405. A call to `POST /api/v1/batch` is one request of the budget, counted when it arrives at the proxy whatever the batch carries; the operations it runs in process never pass through the proxy. The client key is a fourth copy of `clientIp` (`public-api-limit.ts:135`: `x-vercel-forwarded-for`, else the last `x-forwarded-for` segment, else `x-real-ip`); [04](./04-lib-ai-voice-infra.md) has the detail and `client-ip-consistency.test.ts` lists it.

## Detail

### `src/app/api/chat/route.ts`
- **Role:** The site's LLM endpoint — validates and bounds a chat history, serves repeat first-turn questions from the FAQ response cache, otherwise assembles a grounded system prompt from the Velite corpus, and returns a plain-text byte stream with a trailing trace frame.
- **Exports:** `maxDuration` (`= 60`, :25) — segment config; `POST` (async route handler); `GET`, `PUT`, `PATCH` and `DELETE`, all one `methodNotAllowed(["POST"])` handler that answers a JSON 405 with `Allow: POST, OPTIONS`; `OPTIONS = optionsFor(["POST"])`, a 204 with the same `Allow` (:495-501).
- **Reads / depends on:** `@/lib/corpus` (`buildCorpus`), `@/lib/profile`, `@/lib/content` (`allProjects`, `allWork`), `@/lib/llm` (`isConfigured`, `streamWithFallback`, `TRACE_DELIMITER`), `@/lib/rate-limit`, `@/lib/chat-cache` (`faqCacheGet`, `faqCacheSemanticGet`, `faqCacheSet`, `isSemanticMatchEnabled`), `@/lib/telemetry/{with-trace,emit,schema}`, `@/lib/llm-trace` (`THINKING_SENTINEL`, `THINKING_END`, `stripControlBytes`), `node:crypto`. Env: `VERCEL_URL` (:40), `EXTENDED_THINKING` (:287) — plus everything `src/lib/llm.ts` reads (`LLM_PROVIDER`, `LLM_USE_SONNET_5`, `LLM_USE_SONNET_5_5`, `LLM_USE_OPUS_FALLBACK`, `LLM_THINKING_EFFORT`, `BEDROCK_*`) and the cache switches `FAQ_CACHE_ENABLED` / `FAQ_CACHE_SEMANTIC_MATCH` read inside `chat-cache.ts`.
- **Consumed by:** `src/components/chat/use-chat.ts:305` (`fetch("/api/chat", …)`); asserted in `src/components/ask-portfolio.dom.test.tsx:83`; hammered 12× per run by `src/app/api/cron/eval/route.ts:115`.
- **Request → cache → stream → fallback → telemetry path:**
  1. Whole body wrapped in `withTrace(req, "chat", …)` (:138) — mints `traceId`/`spanId`, stamps `x-anvilry-trace-id` on the response, and emits exactly one `http.request` span after the stream finishes (`src/lib/telemetry/with-trace.ts`, `withTrace` / `afterSafeEmit`).
  2. `isConfigured()` → **503** `not_configured` through `apiError` (:139-141), the shared JSON error shape (see "JSON error contract" above).
  3. `checkRateLimit(req, "chat")` **before** any Bedrock call → **429** `rate_limited` with a `Retry-After` header and a hint that names the wait (:145-156). A valid `CRON_SECRET` bearer skips the limiter (the eval cron).
  4. Declared `content-length > 2 * 1024 * 1024` → **413** `payload_too_large` (:163-166). The 2MB ceiling exists for base64 multi-modal attachments; text-only traffic is ~7KB (:158-162).
  5. `req.json()` failure → **400** `invalid_request` with a hint showing the expected `{"messages":[…]}` body (:168-175).
  6. Sanitize: `slice(-MAX_MESSAGES)` where `MAX_MESSAGES = 12` (:27, :182); role filter; string content truncated to `MAX_CHARS = 600` (:28, :192). Attachment blocks are structurally validated — `image` requires `source.type === "base64"` and media type in `["image/jpeg","image/png","image/gif","image/webp"]` (:196-213); `document` requires `application/pdf` (:214-220); `text` blocks are capped at **10000** chars when they start with `"[PDF:"`, else `MAX_CHARS` (:232-240).
  7. Empty block array collapses to `{ role: "user", content: "" }` because the Anthropic SDK 400s on `content: []` (:243-247). Last message must be `user`, else **400** `invalid_request` with a hint saying the array must end with a `user` entry (:254-261).
  8. `ctx.attrs({ messageCount, lastMessageLen })` feeds the auto span without logging prompt text (:271).
  9. **FAQ cache lookup (:273-367).** `skipCache` = header `x-chat-skip-cache` present (any value, :288); `cacheEligible` = not skipped, exactly one message, string content, non-blank (:290-294). Eligible requests try `faqCacheGet(question)` then, only if `isSemanticMatchEnabled()`, `faqCacheSemanticGet` (:301-303), record `cache_hit` / `cache_tier` on the span (:320) and emit one `chat.cache` event (`outcome` hit|miss, `tier`, and on a hit `saved_usd` + `model` + the boolean `reasoning_replayed` (never the text), plus `similarity` for the semantic tier; no key hash, :321-346). On a hit the route returns immediately (see "FAQ response cache" below): no GitHub fetch, no Bedrock, no `llm.attempt`. An exact-tier hit with `extendedThinking` on and a stored `reasoning` string returns `THINKING_SENTINEL` + reasoning (control bytes stripped again, trimmed; empty means the plain body) + `THINKING_END` + answer + U+001E + frame, the framing a live stream has (:313-318, :356-358); a semantic-tier hit never carries reasoning.
  10. `getLiveGithubStats()` awaited (:372) — fetches own `/api/github/stats` with `next: { revalidate: 3600 }`, returns `null` on `!res.ok` or any throw, in which case the `LIVE GITHUB STATS` block is simply omitted from the prompt (:35-67).
  11. `streamWithFallback({ max_tokens: 1024, system: [...], messages }, { traceId, onError, onAttempt, extendedThinking })` (:374-484). The `system` array is **two blocks in a fixed order** (:377-400): (a) `staticSystemPrompt(buildCorpus())` with `cache_control: { type: "ephemeral", ttl: "1h" }` — byte-stable per deploy, this is where the Bedrock prompt-cache value lives; (b) an **uncached** `ADDITIONAL LIVE CONTEXT (updated hourly):` block carrying the GitHub stats, appended after the cache breakpoint. `staticSystemPrompt` deliberately takes only `corpus` (:69-86) so an hourly stats refresh cannot invalidate the cached prefix; folding stats back into block (a) would regress prompt caching. Model chain is `us.anthropic.claude-sonnet-4-6` → `us.anthropic.claude-haiku-4-5-20251001-v1:0` by default; `LLM_USE_SONNET_5=true` puts `us.anthropic.claude-sonnet-5` in front and `LLM_USE_SONNET_5_5=true` puts `global.anthropic.claude-sonnet-5-5` in front, each with Sonnet 4.6 behind it, and `LLM_USE_OPUS_FALLBACK=true` adds `us.anthropic.claude-opus-4-6-v1` right behind the primary (`bedrockChain()` → `buildChain()`, `src/lib/llm.ts:118-126`, `:102-110`). Fallback is only attempted before any `text_delta` event has been received — `emittedAny` is set unconditionally the moment one arrives, even if the text strips to empty; once true, an apology tail is appended and the stream closes (`src/lib/llm.ts:759-786`, which also closes any open thinking phase with `THINKING_END` first). Extended thinking (migrated 2026-09-18 to adaptive thinking) is skipped entirely for Haiku and bumps `max_tokens` to ≥2048 (≥4096 on Sonnet 5.x; 8192, 16000 or 32000 at effort `high`, `xhigh` or `max`) with `adaptiveThinking(model)` + `output_config:{effort: thinkingEffort(model)}` — `{type:"adaptive", display:"summarized"}` + `medium` on Sonnet 5.x, `{type:"adaptive"}` + `low` on everything else, `LLM_THINKING_EFFORT` overriding (any of `low`/`medium`/`high`/`xhigh`/`max`; `xhigh` goes out as `max` to a model that is not Sonnet 5.x) — no more `budget_tokens` (`src/lib/llm.ts:536-537`, `:547-590`, `:158-222`).
  12. `onAttempt` emits one `llm.attempt` event per model attempt with `model`, `attempt_index`, `fell_back`, `ttft_ms`, `latency_ms`, `finish_reason`, `usage`, and `cost_usd` (:412-454), priced per model by `costUsd()` in `src/lib/llm-pricing.ts` (:415-417, :444; left out when the model has no verified price). `onError` additionally `console.warn`s a breadcrumb so `vercel logs --tail` still shows attempt failures if the structured sink is down (:408-411). Still inside `onAttempt`, when `question != null && attempt.answerText != null && !attempt.fell_back` it fires `void faqCacheSet(question, answerText, model, cost, finish_reason, reasoningText)` (:467-480) — the write-through. `attempt.reasoningText` is exactly the `thinking_delta` bytes `llm.ts` sent to the client (accumulated at `src/lib/llm.ts:669-672`; `:723-725` attaches it beside `answerText` when it is non-empty); it goes only to `faqCacheSet`, never into the `llm.attempt` event.
  13. Response: `new Response(stream, { headers: { "Content-Type": "text/plain; charset=utf-8", "Cache-Control": "no-store" } })` (:486-491).
- **Gotchas / invariants:**
  - Cost comes from `costUsd()` in `src/lib/llm-pricing.ts` (imported at :7), not from a table in this file. `cost_usd` is computed once per attempt (:413-417) and, when the model has no verified price, is left out of the `llm.attempt` event (:444) and recorded as a zero saving for the FAQ cache (:476) instead of being priced as Sonnet 4.6. The cache-write TTL the request asks for and the price assumes is one constant, `CACHE_WRITE_TTL` (:390).
  - `PROJECT_SLUGS` / `WORK_SLUGS` are computed at module load from Velite content (:32-33) and interpolated into the prompt (:105-106) — the prompt can never advertise a card slug the client cannot resolve.
  - `extendedThinking` is **on unless** `EXTENDED_THINKING === "false"` (:287) — an unset env means thinking is enabled. It is read once, above `skipCache`, and feeds both paths: the live call (`extendedThinking,` :482) and the hit path, where it gates the reasoning replay (:315).
  - `attempt.error.message` is passed through `redact()` before emit (:432) specifically in case Bedrock echoes a prompt fragment into error text.
  - `X-Chat-Skip-Cache` is unauthenticated on purpose: skipping the cache only forfeits a saving for that one request and grants no privilege; the limiter still applies (:279-284). The eval cron depends on it — if the header name checked at :288 and the one sent at `cron/eval/route.ts:123` ever diverge, the eval silently degrades into a cache test that never exercises the live model.
  - Size guards are header-only in chat (absent `Content-Length` = 0, no post-read backstop) and base64 image/PDF blocks have no per-block cap.

### FAQ response cache (`src/lib/chat-cache.ts`) and its purge route
- **Role:** Full-response cache for `/api/chat`, backed by the shared Upstash singleton (never a per-lambda `Map`), fail-open on every Redis error. Serves repeat first-turn questions with zero Bedrock spend.
- **Tiers:** exact (default on) — `normalizeQuestion` (trim, lowercase, collapse whitespace, strip trailing punctuation) → SHA-256 → key `anvilry:chat:cache:<hash>` (`faqCacheKey`, `:147-149`), and a stored `reasoning` is re-normalized on read because Redis is a trust boundary (`replayableReasoning` / `withReplayableReasoning`, `:173-186`, applied at `:281`); semantic (default **off**, `FAQ_CACHE_SEMANTIC_MATCH === "true"`, `:151-153`) — Titan embedding (`amazon.titan-embed-text-v2:0`, 512 dims, 5s timeout, `src/lib/faq-embeddings.ts:20-28`) compared against the capped index `anvilry:chat:cache:index`, hit when similarity ≥ `SIMILARITY_THRESHOLD = 0.92` (`:298`); the entry's `reasoning` field is deleted (`:326-329`) and the hit type is `Omit<FaqCacheEntry, "reasoning">` (`:124`), so a semantic hit never carries it. Whole cache kill switch: `FAQ_CACHE_ENABLED !== "false"` (`isFaqCacheEnabled`, `:159-161`).
- **Constants:** `FAQ_CACHE_TTL_SECONDS = 24 * 60 * 60` (`:68`, applied to the exact entry and, when the semantic tier is on, to its embedding re-write, `:394`, `:435`; the index sorted set has no TTL of its own); `FAQ_CACHE_INDEX_CAP = 500` (`:71`); index trims sampled 1-in-`TRIM_SAMPLE_EVERY = 20` writes (`:77`, `:402-408`); `MAX_CACHEABLE_ANSWER_CHARS = 4000` (`:84`); `MAX_CACHEABLE_REASONING_CHARS = 4000` (`:90`); `MAX_REASONING_QUESTION_CHARS = 200` (`:96`). Entries are tagged with the id of the deployment that wrote them (`ownDeploymentTag()`, `:193-195`, `VERCEL_DEPLOYMENT_ID`), so another deployment's answer is never replayed (a content-correcting deploy, a rollback, a preview reading production's entries) and a cold start changes nothing (one slot per question: a deployment that answers it again replaces the other's entry); only where the host gives no id is the tag `anvilry:corpus:built_at` (`src/instrumentation.ts`), re-stamped at every production process start.
- **Write gate:** `faqCacheSet` only stores when `finish_reason === "end_turn"` (`:361`), the sanitized answer is non-empty and ≤ 4000 chars (`:364`), and — upstream — `llm.ts` set `answerText` (clean, complete success only; every error path leaves it undefined; `reasoningText` rides along under the same condition, when non-empty) and the route saw `!attempt.fell_back` (`route.ts:470`): an answer served by a fallback rung is streamed but not cached, so a transient primary outage is not replayed for 24 h. It checks completion cleanliness, **not** content safety: a jailbreak that finishes cleanly is cached, which is what the purge route is for. The sixth parameter, `reasoning`, is stored beside the answer only when `replayableReasoning` accepts it (a string, control bytes stripped, trimmed, 1 to 4000 characters) and the normalized question is at most 200 characters, because the summary of a long question is the likeliest to carry what the visitor typed (`:371-374`); otherwise the answer is still cached without it, and an over-long summary logs only its length (`:375-383`).
- **Hit wire format:** one buffered body, not a stream: `answer + U+001E + JSON {model, fellBack:false, cacheHit:true, traceId}` with `X-Chat-Cache: hit` (:348-366). An exact-tier hit whose entry stored reasoning, with `EXTENDED_THINKING` not `false`, is prefixed `THINKING_SENTINEL` + reasoning + `THINKING_END` (:313-318, :356-358): the framing a live stream has, so `answerFromBody` and the chat client's parser read it unchanged, and the Chat view shows a collapsed "Thought for a moment" toggle. A semantic hit, an entry without reasoning and `EXTENDED_THINKING=false` get the plain body above. Clients must handle a non-streamed delimiter-format body in either shape; the frame never carries `usage`.
- **Purge — `POST /api/admin/faq-cache/purge`** (`src/app/api/admin/faq-cache/purge/route.ts`): `requireAdmin` (its own plain-text 401 with `WWW-Authenticate: Basic realm="anvilry"` and `Cache-Control: no-store`, not the shared JSON error shape; :33-34) → declared `content-length > 4KB` → **413** `payload_too_large` (:36-39) → `req.json()` failure → **400** `invalid_request` (:41-46) → post-read `JSON.stringify(body).length > 4KB` → **413** (:52-54) → `question` must be a non-empty string ≤ 2000 chars else **400** `invalid_request` (:59-65) → `faqCachePurge` (`chat-cache.ts:465-485`: `del` the entry key + `zrem` from the index; not gated on `isFaqCacheEnabled()`) → **503** when the result status is `error` (the bare result object, not the shared error shape), else **200** with `{status: "purged" | "not_found", key}` (:67-71). It exports only `POST`: unlike the public routes it has no `methodNotAllowed` handlers, so another method gets Next's empty 405. ### `src/lib/accept-negotiation.ts`, `src/lib/markdown-routing.ts` and `src/next-config.test.ts`

### `src/proxy.ts`
- **Role:** The Next 16 Proxy (formerly Middleware). It runs on the Node.js runtime (the Proxy default, docblock `:12-15`) before any route handler, and has three jobs (docblock `:15-36`): (1) return a real `401` with a `WWW-Authenticate` header for `/admin/*`, which an App Router server component cannot do (it must return React nodes) (`:17-22`); (2) Markdown content negotiation (https://acceptmarkdown.com, `:24-27`), so a request that asks for `text/markdown` gets the Markdown twin of a page; (3) the public-API contract of `src/lib/api-policy.ts` (`:29-35`): version and rate-limit headers, a per-client budget and a JSON 429 for the paths `isPublicApiPath` accepts. The third job has to live here because most of those responses are prerendered or cached and cannot compute a per-client number themselves (`:32-34`).
- **Exports:** `config` (`:41-59`); `proxy(req: NextRequest)` (`:170-187`), which tries the three jobs in that order: the admin gate (`:173-182`), then `servePublicApi` for a public path (`:184`), then `negotiateMarkdown` for everything else (`:186`).
- **Matcher:** twelve entries (`:42-58`): `"/admin/:path*"`, `"/api/:path*"`, `"/.well-known/api-catalog"`, `"/llms.txt"`, `"/llms-full.txt"`, `"/openapi.json"`, `"/feed.xml"`, `"/sitemap.xml"`, `"/robots.txt"`, `"/:page.md"`, `"/:kind(projects|work|articles|notes)/:slug.md"` and `{ source: "/:path*", has: [{ type: "header", key: "accept", value: "(.*)[Tt][Ee][Xx][Tt]/[Mm][Aa][Rr][Kk][Dd][Oo][Ww][Nn](.*)" }] }` (`:56`). The eleven plain entries wake the function for the paths it must gate or stamp; the last wakes it only for a request whose `Accept` header mentions `text/markdown` in any letter case, so a browser or crawler that does not ask for Markdown never invokes it for an ordinary page. The regular expression is spelled out letter by letter because a matcher value is a plain JS regular expression with no flags and media type names are case-insensitive (comment `:38-40`). The public entries must list the same paths as `isPublicApiPath` or the headers silently vanish from the missing one (docblock `:34-35`); `public-api-paths.test.ts` fails if they disagree. `/api/:path*` matches every API route, so the function also runs for chat, voice, the beacon and the cron routes, where it only falls through to `negotiateMarkdown` (`classifyPath` passes `/api/`). `/api/admin/*` (the FAQ-cache purge) is matched but is not an `/admin` path: the gate does not cover it and it relies on `requireAdmin` alone.
- **Auth path** (`:173-182`): `proxy` first checks `pathname === "/admin"` or a path under `/admin/`, so the gate runs before any public-API handling or negotiation. It delegates the whole credential check to `isAdminAuthorized(req.headers.get("Authorization"))` (`:174`) from `src/lib/admin-auth.ts:24-44`, the single implementation shared by this proxy, `requireAdmin` (route handlers, `admin-auth.ts:48-50`) and the `/admin/telemetry` page (which re-checks and calls `notFound()` when unauthorized). It denies when `ADMIN_PASSWORD` is unset (logging an `[admin-auth]` warning on every denied call, never revealing why to the client), when the scheme is not `Basic `, or when the credential mismatches. The supplied value is decoded with `Buffer.from(_, "base64")` (never throws; garbage simply fails the compare) and both `"password"` and `"username:password"` forms are accepted, taking everything after the first colon (`admin-auth.ts:37-41`). The compare is `constantTimeEqual`: SHA-256 digests of both sides through `crypto.timingSafeEqual` (`admin-auth.ts:55-59`), so it is constant-time and length-safe. One 401 exit, `new NextResponse("Unauthorized", { status: 401, headers: { "WWW-Authenticate": 'Basic realm="anvilry"' } })` (`proxy.ts:176-178`), serves every failure mode, so the response never distinguishes an unset env from a wrong password. Success returns `NextResponse.next()` (`:181`).
- **Public-API path** (`servePublicApi`, `:126-168`), in this order: (1) `versionRejection` (`:113-124`) turns a request `API-Version` header other than `"1"` into a JSON 400 `invalid_request` that echoes at most 20 characters of the value (`MAX_ECHOED_VERSION`, `:97`; `:116-123`), for every method, `OPTIONS` and a `POST` included; the function exists so that `servePublicApi` stays short; (2) the path's methods are looked up in the table in `src/lib/public-api-paths.ts` (`allowedMethods(pathname)`, `:132`: `POST, OPTIONS` for `/api/v1/batch`, `GET, HEAD, OPTIONS` for every other public path), and `OPTIONS` is a `204` with that `Allow`, never counted, because a prerendered file would answer it with a bare 405 that contradicts our own `Allow` (`:138-141`), while an `OPTIONS` to the MCP prefix (`MCP_PREFIX`, `:111`) goes on to the route's own handler (`:139`); (3) any method the table does not list, on a non-MCP path, is a JSON 405 `method_not_allowed` with that `Allow` (`:145-154`), so `GET` on the batch path is refused here and `POST` on any other public path too; (4) the request is counted: `publicApiLimiter.hit(publicApiClientKey(req))` (`:156`), and over budget it is a JSON 429 `rate_limited` whose hint gives the seconds to wait, stamped with `Retry-After` and the `RateLimit` fields like any counted response (`:158-166`); a `POST /api/v1/batch` is one such request, counted here before the route runs; (5) otherwise `negotiateMarkdown(req)` runs, which passes every public path through, and the response is stamped (`:167`). `stamp()` (`:100-109`) sets `API-Version: 1`, the `RateLimit-Policy`, `RateLimit` and older `RateLimit-Limit/-Remaining/-Reset` fields from `rateLimitHeaders` (`src/lib/public-api-limit.ts:112`) and any `Deprecation`, `Sunset` and successor `Link` from `deprecationHeaders(pathname)` (none today; `Link` is appended, not overwritten, `:103-107`). The refused requests (400, 405, `OPTIONS`) carry the version header but no `RateLimit` fields.

Nothing acceptable (`null`) on a page that really is negotiated returns `406` with the plain-text body `NOT_ACCEPTABLE`, `Content-Type: text/plain; charset=utf-8`, `Vary: Accept` and `Cache-Control: no-store` (`:61-62`, `:78-89`); on any other route it falls through. Otherwise HTML wins: `NextResponse.next()`, with `Vary: Accept` appended for a negotiated route through `appendVary` (`:91-94`). `next.config.ts` (`headers()`, `:286-300`) asks for the same `Vary: Accept` and adds a `Link: rel="alternate"` statically, on `/`, on each of the ten pages and on `/<kind>/<slug>`; Next replaces `Vary` on HTML responses (the comment at `next.config.ts:265-267` says so), so for HTML only the `Link` lasts and `Vary: Accept` is reliably present on the Markdown replies alone (`markdownResponse`, and the 406).

- **Role:** Next 16 server instrumentation hook — one structured config-snapshot log per server process start, plus a production-only process-start timestamp (the dashboard's Corpus age; the FAQ cache's tag only where the host gives no deployment id).
- **Exports:** `register()` (async).
- **Reads / depends on:** `process.env` only for the snapshot; dynamically `import("@/lib/redis")` at :96.
- **Behaviour notes:** returns immediately when `process.env.NEXT_RUNTIME === "edge"` (:35). Builds a `config` object with: `vercel_env` (enum of `production|preview|development`, fallback `"local"`), `node_env`, `region` (`VERCEL_REGION ?? AWS_REGION ?? "unknown"`), `deployment_id` (a boolean: `VERCEL_DEPLOYMENT_ID` is present, never the id), `flag_driver` (`vercel|local`, fallback `local`), `flags_sdk_configured` (`FLAGS` present), `flags_secret_configured` (`FLAGS_SECRET` present), a `beast_flags` block (`NEXT_PUBLIC_ORB_POSTPROCESSING`, `NEXT_PUBLIC_INK_TRANSITION`, `NEXT_PUBLIC_SKILL_TREE`, `NEXT_PUBLIC_404_ORB`, `NEXT_PUBLIC_VISITOR_COUNTER`, each `=== "true"`), an `integrations` presence-only block (`BEDROCK_ACCESS_KEY_ID`, `UPSTASH_REDIS_REST_URL`, `GOOGLE_TTS_API_KEY`, `GITHUB_TOKEN`, `ADMIN_PASSWORD`, `TELEMETRY_IP_SALT`), `llm_provider` (`bedrock|anthropic`, fallback `bedrock`) and `llm_sdk` (`anthropic-bedrock|aws-sdk-bedrock`) (:39-81). - **Gotchas / invariants:** only booleans and safe enum values are logged — never a secret value (:12-14). Grep handles are distinct and load-bearing: `[config]` here, `[trace]` for telemetry spans (`src/lib/telemetry/emit.ts:61`), `[vitals]` for RUM (`src/instrumentation-client.ts:52`), `[flags]` for flag resolution (`src/lib/flags.ts:45`). `discovery_badges` is deliberately omitted from `beast_flags` because it is runtime-resolved and logged by `getDiscoveryBadgesEnabled()` (:60-61). ### `src/instrumentation-client.ts`
- **Role:** Next 16 client instrumentation hook — registers web-vitals reporting and the two window-level error listeners that sit under the React boundaries.
- **Exports:** none. The whole file is a module-load side effect guarded by `if (typeof window !== "undefined")` (:46); the framework contract is "side-effects at module load are run" (:5-7).
- **Reads / depends on:** lazy `import("web-vitals")` (:50) and lazy `import("@/lib/telemetry/beacon")` (:59).
- **Behaviour notes:** `onLCP`/`onINP`/`onCLS` all report via `console.info("[vitals]", name, Math.round(value), rating)` — no Redis, no API route (:50-56); the whole vitals block is `.catch()`-swallowed so observability can never break the page. Two listeners are registered: `"error"` (:74) and `"unhandledrejection"` (:86), each calling `sendErrorBeacon` with `source: "window"` / `"unhandledrejection"`, `url: window.location.href`, `userAgent: navigator.userAgent`, `level: "error"`. Rejection reasons are narrowed four ways — `Error` instance, object with a string `.message` (and optional `.stack`), non-null primitive via `String()`, else the literal `"unhandled rejection"` (:93-106).
- **Gotchas / invariants:** the **dedupe contract** is the subtle part (:26-39, :65-72): React boundaries set `window.__anvilry_error_recently__ = Date.now()` *before* they beacon, and both window listeners suppress if that timestamp is within `DEDUPE_MS = 100`. It is a timestamp rather than a boolean specifically to avoid a `setTimeout` cleanup that would add an event-loop turn and re-create the race. Two genuinely distinct errors 200ms apart still both report. If a boundary stops setting that global, every render error double-reports to `/api/error`. Both `import()`s are dynamic to keep `web-vitals` (~4KB) and the beacon module out of the SSR bundle and off the critical path.
