# Invariants, Gotchas & Danger Ledger

> Part of the Anvilry v3.7.0 codebase index. Master entry point: [docs/index/README.md](./README.md)
> **Baseline:** describes Anvilry v3.7.0 (package `anvilry` 3.7.0), i.e. `main` at `a929932` (package `anvilry` 3.6.0) plus five later fixes, each described by
> behaviour — notes are hidden at the data layer while `NOTES_ENABLED` is off (`allNotes` is empty; the raw list
> stays available as `publishedNotes` for the `/notes` route files, and articles whose only destination is a note
> are dropped too); rate limiting has per-class buckets (`chat` / `voice` / `beacon`) with a `CRON_SECRET` bypass
> for the eval cron, built on the shared `src/lib/cron-auth.ts` that all five cron routes now call; admin auth goes
> through one `isAdminAuthorized` shared by `src/proxy.ts`, `requireAdmin` and the telemetry page; the command
> palette's talk-mode entry is gated on `isVoiceViewActive`; and the bundle-budget gate asserts `MIN_ROUTES = 17`
> while the dead `ArticleCard`, `Button`, `EmptyState` and `ArticleJsonLd` were removed. Every count and
> `path:line` below was re-read against that tree (measured in the worktree at `8e9e73e`; `package.json`'s own version, bumped at the release cut, is `3.7.0`). "On this branch" /
> "this branch" in older rows is historical wording from the v3.5.0–v3.6.0 index-repair branch — read it as
> "already fixed in the tree this file describes".

**Scope:** the cross-cutting rules of this repo — every check that fails a build, every contract that two or
more files must agree on, every environment/platform quirk that has already bitten once, and every place where
a wrong edit produces no error at all. Nothing here is new information; it is the union of sections 01–14b,
re-cut by blast radius instead of by directory. Every row carries a `path:line` cite.

Three facts frame everything below:

1. `package.json:11` — `"build": "velite --clean && vitest run && next build && pagefind --site .next/server/app --output-path public/pagefind"`.
   The `&&` chain is what turns this repo's unit tests into deploy gates, and Pagefind is its last link — a red
   test also blocks the search index. Verified verbatim.
2. `next.config.ts:203` — `cacheComponents: true`. This is why no page or route handler in `src/app` exports
   `runtime`, `revalidate`, or `dynamic`, and why several constructs exist only as removal comments.
3. `.gitignore:45` — `.velite` is gitignored, while `src/lib/content.ts:14` imports `"../../.velite"`. Nothing
   type-checks, tests, or builds until Velite has run.
